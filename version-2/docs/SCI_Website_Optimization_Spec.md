# ASUS SCI 影分身評估工具｜網頁優化與工程實作規格

版本：v1.0 提案版  
日期：2026-09-30  
用途：提供工程師、UX／UI、行銷與產品團隊實作及校準。  
本次交付：規格文件；未修改原始 HTML。

## 1. 最新決策與專案邊界

本文件以最新討論為準：先由使用者的實際工作流計算 SCI，呈現每月釋放工時、每月節省 Token 與每月省下費用，再推薦符合這些任務自動化需求的地端設備。

### 1.1 必須實作

- 僅保留三大族群：SOHO、Education、SMB；可在族群內增加工作方向標籤，不能增加第四族群。
- 先選身分，再選「本來就會做的任務」，不要求使用者事先瞭解 AI。
- 收集任務頻率、規模、目前人工耗時與目前做法，才能估算現況及改善空間。
- SCI 呈現「目前」及「導入建議 Agentic 工作流後」兩個狀態，分數越高代表人工負擔解放程度越高。
- 顯示時間效益及其換算的人力成本價值；明確區分這個價值與實際現金支出節省。
- 設備依工作流、規模、同時執行需求及軟體相容性推薦，不能按族群固定配機。
- CPU 與 MB 在同一結果中同時顯示 AMD／Intel 方案；其餘零件共用一組。
- SCI 演算法與參數集中管理，可替換；前台只顯示 SCI 簡化定義，不顯示流程涵蓋、自主程度、例外率、步驟權重及設備路由門檻。

### 1.2 本階段不做

- 不建立真正操作 ERP、LMS、社群平台的 Agent；本工具是需求評估及選購導引。
- 不要求登入、不讀取使用者實際檔案、不要求貼入公司機密資料。
- 不推導「低 SCI＝電腦很差」，不推導「買設備＝自動得到所有效益」。
- 不宣稱零延遲、100% 隱私、零人工作業、所有模型皆可執行。
- 不在缺少費用輸入的情況下，自動產生雲端月費、訂閱浪費或設備回收期。
- 不在這次實作中執行對外發布、開立發票、正式評分或自動核准等動作。

### 1.3 定義與名稱

統一使用原主管版本：**SCI＝Shadow-Clone Index，影分身指數**。移除現有 HTML 的 Shadow Intelligence Index／影子智慧指數，避免名稱前後不一致。

前台簡介：

> 看看你的日常工作，有多少能交給 AI 影分身。依照你的任務與使用頻率，估算能釋放的時間，並找到適合的設備配置。

Agentic AI 在此指能依工作流程串接工具、整理輸入、執行多步驟任務及產出待確認成果的助手；人工仍需設定方向、檢查重要內容及處理例外。一般計算與格式化可以使用程式，不必每步都呼叫模型。

## 4. 建議問答架構：四步驟，結果內推薦設備

保留四步主架構，避免變成很長的專業硬體問卷。Step 3 用分組卡片漸進展開；工程細節不出現在消費者流程中。

### Step 1｜你的主要工作身分

- 單選 SOHO 自由工作者／Education 教育與學習／SMB 中小企業與團隊。
- 可選工作方向標籤，僅調整卡片排序，不給固定分數、不隱藏其他同族群任務。
- SOHO：影音與設計／內容與行銷／接案與行政。
- Education：教師／學生／研究人員。
- SMB：電商與業務／行銷與客服／行政與營運。
- 不預設族群；選擇後才能下一步。同族群再次點擊保留答案。

### Step 2｜你平常需要處理哪些工作？

- 問「原本要做的工作」，不要問「核心 AI 需求」。
- 每族群先顯示主管提供的三項核心工作流，其餘按標籤排序，可展開「更多工作」。
- 卡片：名稱、一次工作量示例、原本要做的步驟、分身可協助的環節。
- 詳細說明內顯示人工確認環節，但不暴露估算比例或公式。
- 初版選 1–6 項；每項是完整工作流，不能將其子步驟再列為可重複加總的任務。
- 提供「我的工作不在清單內」：只做未涵蓋提示與可選回饋；不自動為自由輸入產生分數或精確設備。
- 如果沒有適合工作，允許查看一般入門指南，不強迫產生假分數。

### Step 3｜這些工作通常花你多少時間？

每個任務使用一致欄位：

| 欄位 | 必填 | 互動與定義 |
| --- | --- | --- |
| 工作規模 | 是 | 小量／標準／大量；任務專屬說明，例如報價一份、五份、十份；不是模糊「輕度／重度」 |
| 頻率數量 | 是 | 正整數，預設未填；1–10 快捷選項＋數字輸入，允許超過 10 |
| 頻率週期 | 是 | 每週／每月，預設每週；數量與週期一併顯示 |
| 目前做法 | 是 | 大多手動／AI 輔助但仍手動串接／已有自動化流程 |
| 目前每次人工投入時間 | 是 | 分鐘；顯示依規模、做法產生的「參考值」並要求確認，可修改 |
| 同時處理需求 | 共用必填 | 多半依序／約 2 項同時／3–4 項同時／5 項以上；未知可選不確定 |
| 同時使用人數 | SMB 顯示 | 單人／2–5／6–10／10+；此欄只影響負載，不自動乘人力效益 |
| 人力每小時成本 | 選填 | NT$／小時，自填；跳過即隱藏金額，不按族群預設 |

欄位旁說明：「填入你實際操作、整理、檢查與修改的時間；不包含電腦自行處理時你可離開的等待時間。」

數量口徑：問「這項工作整體每週／每月發生幾次」，一次依該任務的標準單位計算。SMB 若已填全團隊總次數，不能再乘員工數；需要多人配合的單次任務，人工時間是所有參與者投入分鐘的總和。結果以人時呈現，不能暗示全團隊節省的人時全屬某一人。

成本區說明：「將釋放的人工時間換算為成本價值；不代表薪資或帳單會等額減少。」不要求薪資證明。

驗證規則：頻率 1–10,000，人工分鐘 0.1–10,080，唯一成本輸入大於 0 且最高 10,000,000；所有輸入拒絕 NaN／Infinity／負數。接近上限或折算單人每月超過 240 人時，先要求核對規模／單位，不能默默截成 240。SMB 顯示「是否包含多人投入」校正提示，不設全團隊 240 上限。

### Step 4｜你的影分身工作效益報告

呈現順序：

1. 目前 SCI 與預估可達 SCI，並列且明確標示。
2. 每月目前人工投入、預估可釋放人時、導入後仍需人工投入。
3. 固定三項效益數據：每月釋放工時、每月節省 Token、每月省下費用；卡片下方不加計算說明小字。
4. 工作流逐項前後比較與人工保留環節。
5. 由選項生成的影分身團隊。
6. 根據工作負載的設備建議，CPU／MB 雙平台＋共用零件。
7. 任務對應教學／有效活動／下載報告等 CTA。

主要結果例句：

> 在你選取的工作中，導入建議工作流後，預估每月可釋放約 X 人時。你仍需確認重要內容與處理例外；設備建議依這些任務的規模及同時執行需求產生。

若全為單人：可稱「小時」；多人或未確認：使用「人時」。不要顯示「原本的整份工作」／「全部工作」自動化程度，本次只評估已選範圍。

## 7. SCI 暫定計算規格：內部使用，不出現在前台

### 7.1 計分解釋

SCI 代表已選工作範圍內，相對全手動基準的人工負擔解放比例；不是硬體跑分，不是個人能力評分。當前 SCI 與可達 SCI 使用同一任務範圍、同一基準分母。

只有頻率／任務選擇不足以得到當前自動化程度，因此第 4 節的目前做法與人工時間為必要輸入。低頻手動使用者當前 SCI 可以是 0；高頻但高度自動化使用者也可以很高。

### 7.2 參數與公式

對每項任務 i：

- `F_i`：每月次數。每周次數×52÷12；每月次數直接使用。顯示小數，內部不先取整。
- `M_i`：該規模全手動一次基準人工分鐘，來自版本化任務種子。
- `C_i`：使用者確認的目前每次人工分鐘。
- `A_i`：由該任務的流程步驟模型推算出的導入後人工參考分鐘，含操作／確認／修改／例外。
- `T_i = min(C_i, A_i)`：建議目標，不強迫已比參考更有效的使用者變慢；若 C_i≤A_i，提示該項當前已有效，不產生額外時間節省。

當 C_i>M_i，採用 `effectiveM_i=max(M_i,C_i)`，標記基準被個人耗時調整；不要截掉使用者實際時間。當前值極低時提示確認口徑，但不自動修改。

每項固定任務拆成 5 個主要流程步驟。每個步驟 j 具有工作量權重 `W_j`、可交付比例 `D_j`、人工審核比例 `R_j`、例外率 `E_j` 與例外處理量 `X_j`：

```text
retainedRatio_j = (1 − D_j) + (D_j × R_j) + (D_j × E_j × X_j)
retainedHumanRatio_i = Σ(W_j × retainedRatio_j)
A_i = effectiveM_i × retainedHumanRatio_i
```

流程涵蓋率、自主程度與運算強度保留為內部分析欄位，用來校準人工保留時間與設備路由；前台不將它們包裝成額外分數。目前 24 項任務各有 5 個步驟，共 120 筆流程資料，版本為 `workflow-model-v1`。

```text
baselineMinutes = Σ(F_i × effectiveM_i)
currentMinutes  = Σ(F_i × C_i)
targetMinutes   = Σ(F_i × T_i)

SCI_current = 100 × (1 − currentMinutes / baselineMinutes)
SCI_target  = 100 × (1 − targetMinutes / baselineMinutes)
SCI_gap     = SCI_target − SCI_current

currentHoursMonthly = currentMinutes / 60
targetHoursMonthly  = targetMinutes / 60
savedHoursMonthly   = (currentMinutes − targetMinutes) / 60
```

空任務、baselineMinutes≤0 不產生分數；顯示未能估算。SCI 理論範圍 0–100；浮點誤差 clamp 處理，但不能設置 12／95 的營銷底分與上限。儀表顯示四捨五入整數與「分」，差距稱「點」，不把 SCI 百分比與實測覆蓋率混為一談。節省工時顯示 1 位小數，費用與 Token 也以同一筆 1 位小數工時為結算口徑，確保畫面數字可直接驗算；金額取整數。

目前做法僅用於人工時間的可編輯參考：手動以 M 為參考；AI 輔助採 `0.58M + 0.42A`；已有自動化採 `0.18M + 0.82A`。必須由使用者確認，比例不是已測事實。最終以確認的 C 為準，不重復將做法系數乘進公式。

### 7.3 等級：僅依當前 SCI 呈現

| 當前 SCI | 等級 | 前台語氣 |
| --- | --- | --- |
| 0–19 | L1 工作待分擔 | 多數已選工作仍需親自處理 |
| 20–39 | L2 分身初步協助 | 已減輕部分重復工作 |
| 40–59 | L3 部分流程串接 | 已有一定流程協助 |
| 60–79 | L4 分身協作 | 多數已選工作負擔已有協助 |
| 80–100 | L5 高度流程化 | 已選工作的人力投入已顯著降低 |

等級不自動決定設備等級；可達 SCI 僅標記「預估可達」。沒有潛力差距不改低當前分，不強推高階設備。

### 7.4 明確限制

- 簡化 SCI 不再乘角色數或流程步驟覆蓋率，避免重復扣除及數量偏差。
- SCI 不隨頻率機械下降；頻率改變的是加權與可釋放時間。
- 同一任務全部頻率同時乘 2，SCI 應相同、可釋放時間應乘 2。
- 成本費用為必填，只輸入一個數字；可選擇以時／週／月輸入，系統分別以 1、40、160 小時換算成統一時成本。輸入可代表使用者認定的工作成本或目前雲端訂閱成本，不影響 SCI 與設備級別。
- 本公式為估算，不保證升級後達到該分數；需要相應工具、系統接入及人工審核。
- 前台可顯示簡化公式、定義與口徑，但不呈現內部任務種子或設備路由權重。
- 如果要求演算法不可被查看，需後端計算；純瀏覽器版本只能做到不在 UI 呈現，不能保證 JS 無法被查看。此項為工程架構說明，不放進消費者文案。

## 8. 時間與費用呈現

### 8.1 單一成本費用換算

```text
normalizedHourlyCost = inputCost / periodHours
periodHours = 1（時）／40（週）／160（月）
monthlySavedCost = savedHoursMonthly × normalizedHourlyCost
monthlySavedTokens = monthlySavedCost / 190 × 1,000,000
```

Token 以內部基準每 100 萬 tokens 約 NT$190 換算，屬費用等值而非模型實際 token 計量。成本結果不拿去與設備售價計算保證回收期。

已有自動化且 target=current 時，顯示「當前該項已達到此參考流程的人工投入水平」與 0 額外釋放時間；提供其他工作流建議，不硬湊正收益。

### 8.2 計算驗收樣例

S01 標準，20 次／月，M=25、C=25、A=8，時薪 NT$300：

- 基準=500 分鐘；目前=500；目標=160。
- 當前 SCI=0；目標 SCI=68；差距=68 點。
- 當前人工=8.333…小時；目標=2.666…；節省工時顯示並結算為 5.7 小時。
- 每月省下費用=NT$1,710；每月節省 Token 約 9M。
- 若同任務 C=5，目標=min(5,8)=5：當前與目標 SCI 均為 80，新增節省為 0。
- 若改填週成本 NT$12,000，系統以 40 小時換算為 NT$300／小時，結果相同。

## 10. 設備推薦引擎

### 10.1 推薦原則

設備推薦是「在指定推廣設備池中，適合此工作負載的候選配置」，不是全球市場最低必要規格。

本頁設備策略採地端優先：強調工作檔案與流程留在自有設備、降低長期雲端訂閱／用量計價／網路連線依賴，並把持續可用與可擴充的本機算力作為主要購買價值。不得宣稱買設備後會自動完成工作、完全取代所有雲端服務或保證固定速度倍數。

族群只改任務清單。時薪、人力成本價值、使用者看了哪個優惠都不能作配機規則。SCI 不得單獨推高設備，但可與工作量及運算強度共同判斷高階影分身需要承接的持續算力；角色數或分身數也不能直接換算 GPU 數量。

### 10.3 影分身戰力

前台除 SCI 外，只新增「影分身戰力」作為設備指標；流程涵蓋率、自主程度與運算強度均不直接展示。影分身戰力代表推薦設備在本地模型、多工具並行與重負載工作上的相對運算餘裕，不代表特定模型的 benchmark 或固定加速倍數。

前台不再顯示 62／81／94 等數字分數，也不顯示 Entry／Mainstream／High-END。設備池改為五級：A 為初階，其上依序為 A+、S、S+、SS。等級來自設備規格；任務規模、流程運算強度、媒體／程式 profile、同時執行需求及總工作量負責路由。SS 僅用於高 SCI 且算力需求超大、工作負載超重的組合，不能只因 SCI 高就推薦。

### 10.4 可執行的首版規則

1. 任務原始 `baseTierByScale` 先映射為 A／A+／S，仍取各任務最高需求而不是平均。
2. 並行、多人、批次頻率、大量媒體／程式與工作流運算強度可將結果提高至 A+ 或 S。
3. 加權運算強度達 3.5／5，且每月全人工基準達 160 小時、5 項以上並行或至少 3 項大量任務之一，才進入 S+。
4. SS 必須同時符合：導入後 SCI 至少 75、加權運算強度至少 3.35，並且每月全人工基準達 320 小時，或 5 項以上並行且至少 3 項大量任務。
5. A 為初階地端協作；A+ 為進階多工具；S 為高負載桌上型；S+ 為工作站／Blackwell 專業算力；SS 為 ET900N G3 極重度算力。

### 10.4 CPU 品牌與 GPU 品牌是不同維度

- AMD CPU 路徑可搭配 NVIDIA GPU；Intel CPU 路徑也可搭配 AMD GPU。
- 使用者要求的 Intel／AMD 並列只針對 CPU／MB；不能把它理解成兩套顯示卡。
- R9700 與 RTX 5090 即使都是 32GB，不能假設工具支援、速度或模型效能相同。
- 原 HTML 的 Stable Diffusion、其他工具若指定 CUDA，不能直接推薦 AMD GPU；先查所選版本與後端是否經驗證。
- 共享 GPU 不相容時，允許推薦池內另一張已驗證 GPU 並說明是軟體相容性理由；不是因消費者身分升檔。如果整個推薦池無法滿足，顯示待評估。

### 12.5 版本與隱藏演算法

- 分數、任務參考、硬體目錄分別版本化，避免改公式時一起改產品。
- 首版可純前端評估，符合「不暴露在前台」的 UI 要求；不能宣稱瀏覽器代碼保密。
- 真正隱藏公式需後端 `POST /assessment`。對輸入做服務端驗證，不信任客戶端已算金額或 tier。
- 不調用生成式模型隨意給分；首版計算確定性、可回歸、同答案同結果。
- 使用者答案變更時整份 result 失效並重算；下載使用當前 result snapshot，不拼接舊 DOM。

## 14. 下載與分享圖

- 保留 PNG 預覽＋下載，提供精簡分享版及完整報告版；初版若只做一種，優先完整報告。
- 內容必含：三大族群、已選任務範圍、當前／目標 SCI、時間效益、金額類型、任務摘要、所有同級推薦機台的完整規格及估算注記；不能只完整顯示第一台，再把其他機台縮成文字候選。
- 不含公式、系數、未核准折扣、100% 隱私、虛構影片效果、原雲端費用。
- Canvas 高度依任務數與推薦機台數動態增加；每台推薦機台各有完整設備區塊，不得因第二台以上設備造成裁切或壓縮。
- 超長時採用分頁 PNG，或完整長圖；至少 1／3／6 任務都無重疊、裁切。雙平台名稱不能被省略號截到無法辨識。
- 時間與金額顯示和網頁一致；費用必須使用同一筆 1 位小數節省工時計算，避免顯示值與可驗算結果不一致。
- 等待 `document.fonts.ready`，圖片跨來源若要畫入 canvas 必須處理 CORS；失敗回退文字版產品資訊，不阻擋報告下載。
- 日期與文件名按 Asia/Taipei 生成；不要 `toISOString().slice(0,10)` 直接用 UTC 日期。
- 重算／關閉預覽／重置要 revoke Object URL；下載狀態與錯誤可見。
- 導出的產品連結可用文字網址或後續 QR，但 URL 必須來自核准配置，不生成不存在頁面。

不要強制留資才看結果或下載；未來若新增訂閱／留資，需獨立授權與用途。

## 17. 工程驗收標準

### 17.1 功能與狀態

- 三族群各 8 項、共 24 唯一 ID；主管原 9 工作流全部可找到。
- 可選 1–6 任務；沒有適合任務有無分數替代路徑。

- 自由回饋不被當成可精算 recipe；重復產出有去重確認。

### 17.2 計算

- 第 8.3 節固定樣例全部符合。
- 同任務頻率倍增，SCI 不變、月時間與成本價值倍增。
- 修改時薪不改變 SCI／時間／設備；未填不顯示金額。
- 低頻手動不會假冒高 SCI；已自動化不會被頻率壓低分數。
- current≤target SCI；時間節省不大於目前人工投入；零改善可正常顯示。
- 若 C>M，則 effectiveM 改為 C 並留內部標記，不出現負 SCI。
- 無合法任務、不合法數值不產生 NaN／Infinity／虛構分數。
- 節省工時先四捨五入到 1 位小數再乘換算時薪，不可取整小時；例如 62.5 小時 × NT$200 必須得到 NT$12,500。
